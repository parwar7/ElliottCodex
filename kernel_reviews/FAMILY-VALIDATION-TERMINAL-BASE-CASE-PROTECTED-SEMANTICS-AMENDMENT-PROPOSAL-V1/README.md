# Family-validation terminal/base-case protected-semantics amendment proposal

This package is proposal evidence only. It is not an approved Brain amendment, methodology baseline, Runtime implementation, family producer, or certificate authority.

The source-derived path does not contain a positive terminal/base case. The protected corpus requires family-specific internals, warns that aggregation can conceal them, and directs invisible required internals to finer data or unresolved status. It does not define an indivisible wave, a primitive motive/corrective structure that needs no internal family proof, or a deterministic general completion authority.

No safe enabling project policy was found within the approved boundary. A resolution floor would turn missing internals into validity. A fixed recursion depth would weaken the certificate claim. Human or caller adjudication would be an untrusted family declaration. Cardinality would not prove family. An atomic price transition is not source-defined as either existing family kind. Each route is therefore rejected.

The included Brain diff is a narrow, non-enabling governance clarification only. It explicitly preserves `INTERNALS_UNRESOLVED`, prohibits resolution exhaustion from becoming positive validity, and states that no family producer is authorized until separate protected authority defines a deterministic primitive and completion requirements. It unlocks neither family and is not recommended as an enabling amendment.

P005 and P006 remain frozen. Position and endpoint authority remain separate. The current family-certification contract remains unchanged, sealed, empty, and compatible with a future genuine producer through its reviewed extension model.
