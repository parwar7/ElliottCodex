# CANDIDATE-ANALYSIS-ENVELOPE-CONTRACT-V1

This additive logical baseline records `PROJECT_ANALYSIS_INFRASTRUCTURE`. Its consistency conventions are `PROJECT_OPERATIONAL_POLICY`, not Elliott methodology.

`CandidateAnalysisEnvelope` transports one exact caller-proposed `AnalyzedWaveSubject`, opaque `candidate_id` metadata, an optional exact `OrderedChildBinding`, ordered methodology-evaluation and observation-attachment tuples, an optional exact `BoundedRecursiveAnalysisResolution`, and provenance references. Construction means only that the live same-process package satisfies infrastructure consistency checks. It establishes no pattern, wave label, degree, parentage, timeframe, completion, direction, family, validity, evidence, rank, or decision.

`CandidateMethodologyEvaluation` retains an exact behavior ID, exact input identity, exact result identity, exact subject, and provenance. A private reviewed compatibility tuple admits exactly ten current behavior pairings. Type-name matching, duck typing, mappings, subclasses, dynamic imports, and unknown IDs fail closed. P023 requires the existing live subject-bound wrapper. Cardinality inputs/results retain exact binding identity. The no-rescue result must retain its exact live input certificate. Legacy behavior results without subject identity remain transport-only and are not inferred to validate the envelope subject.

The duplicate policy rejects repeated attachment of the same behavior with the same exact input identity. Multiple evaluations of one behavior are permitted only with distinct exact input objects, retain supplied order, and receive no ranking or winner selection.

`CandidateObservationAttachment` accepts only exact existing subject-bound observed-price observations or endpoint pairs. It retains their exact identities and subject, but adds no pivot, structural endpoint, orthodox endpoint, wave origin/end, or completion meaning.

The optional operational resolution is revalidated and must retain the identical subject. The envelope does not create, recompute, upgrade, or transform operational state. It is rejected by both certification APIs.

Recursive identity snapshots detect low-level changes to attachment fields and nested dataclass/tuple content when the objects are consumed or copied. Ordinary construction is frozen, slotted, identity-based, subclass-sealed, and non-pickleable. No hostile-interpreter, cryptographic, durable cross-process, or provenance-authentication guarantee is claimed.

The approved `SOURCE_DERIVED_BASE_CASE_NOT_FOUND` finding remains unchanged. No behavior, producer, family issuance, candidate discovery, timeframe mapping, degree inference, evidence, indicator, ranking, TradingView, provider, monitoring, alert, or execution logic was added.
