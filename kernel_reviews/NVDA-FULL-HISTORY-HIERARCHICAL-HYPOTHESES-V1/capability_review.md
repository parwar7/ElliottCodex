# Capability review and search policy

## Main finding

Existing public APIs can enumerate exact scoped pivot hypotheses and re-enter
internal-requirement evaluation using a genuine child-family bridge. No shared
contract or Elliott methodology amendment is needed for this bounded exploration.
This does not establish a full-history count or current-wave position.

This review separates four capabilities:

1. Historical search: all three declared regions are scheduled, with unvisited
   and cross-region-excluded windows separately accounted for. This is NOT
   exhaustive search of all full-history combinations.
2. Historical span: an operational six-point coarsening proposes structures
   between first and last Monthly geometric pivots. It does not make the
   first available observation, IPO or first pivot an orthodox wave origin.
3. Hierarchical links: each expanded child bundle is taken from an exact
   RecursiveChildFamilyEvaluationResult. Its generated evidence binds to the
   originating requirement, child subject, observation selection and candidate
   identities. Re-entry uses that bundle, not a reconstructed string or ID.
4. Current position: unresolved. No existing developing-position template is
   supplied. A last endpoint or an operational recursion leaf cannot establish
   completion, current wave or next wave. Trailing observations are counted.

## Inspected interfaces

- src/elliott_runtime/analysis/candidate_generation.py:
  CandidateGenerationRequest.scoped_pivots accepts a chronological tuple of
  exact source-result pivots. _validate_scoped_pivots rejects foreign/duplicate
  objects. Configured skip/span counts refer to the scoped sequence, not the
  full original pivot set. The report explicitly identifies coarsened indices
  and source pivots excluded from each job so this distinction is not hidden.
- src/elliott_runtime/analysis/family_hypotheses.py:
  build_family_evaluation_hypotheses creates hypothesis-only family selectors
  with exact OrderedChildBinding and proposed children. Direct cardinality is
  not positive family classification.
- src/elliott_runtime/analysis/family_internal_subdivisions.py:
  evaluate_family_internal_subdivisions accepts exact FamilyHypothesisBridgeResult,
  including the existing child evaluation's bridge. It creates source-derived
  requirements and reuses aggregate_supplied_child_resolutions. No synthetic
  family proof is supplied.
- src/elliott_runtime/analysis/finer_child_observation_selection.py:
  ChildObservationSelectionRequest requires exact requirement/window,
  explicit finer observations in a genuine transport bundle, and existing
  resolution comparison. Full/partial/no-window coverage is retained.
- src/elliott_runtime/analysis/recursive_child_candidate_generation.py:
  generate_child_candidate_evidence makes exactly one bounded layer per call.
  Missing finer coverage does not fall back silently to invented or resampled
  observations. Source endpoint windows and scoped geometry are retained.
- src/elliott_runtime/analysis/recursive_child_family_evaluation.py:
  evaluate_recursive_child_family_hypotheses creates one compatible family
  evaluation layer per call. Its exact returned bridge feeds the next existing
  internal evaluator. The orchestration loop composes calls; it does not change
  the one-layer function or add a certificate/validation engine.
- src/elliott_runtime/analysis/normal_impulse_partial_evaluation.py:
  evaluate_normal_impulse_partial_scope receives the exact root bridge or exact
  child-generation result. Role mapping, P004 fatality, P005 snapshot-bound
  percentage sufficiency and repaired ancestry remain owned by this API.
- src/elliott_methodology_kernel/recursive_candidate_composition.py:
  compose_recursive_candidate is used only for the same genuine bounded-result
  observation-transport leaf as the previous experiment. Empty operational
  children do not assert Elliott terminality. A new aggregate full-tree
  methodology result is NOT constructed or claimed.
- src/elliott_methodology_kernel/multi_degree_candidate_composition.py:
  degree checks require caller declarations. None is supplied in this run;
  no timeframe/depth degree declaration is invented.
- tools/nvda_bounded_report.py:
  reuse exact endpoint and P004/P005 export mapping, duplicate display grouping,
  display aliases and CSV output. Legacy analyze remains untouched.

## Protected support and limits

Protected docs/elliott/MASTER_PROTOCOL.md Steps 1, 3 and 6 and
docs/elliott/DEGREE_RECURSION_BRAIN.md sections 2, 3, 5, 6 and 7 supply
the source-locked perspective, recursion and unresolved-degree constraints.
These instructions are not a mechanical pivot-significance algorithm.
The approved source set and classifications remain governed by
docs/elliott/SOURCE_POLICY.md.

Internal source-defined expectations remain those already encoded and referenced
by FamilyInternalSubdivisionRequirement. P007/P008/P009 cardinality and ending
diagonal cardinality are not full family proofs. Normal Impulse remains partial
P004/P005 with frozen P006. Flat/Triangle freezes and
SOURCE_DERIVED_BASE_CASE_NOT_FOUND are unchanged.

The search partition, six-index coarsening, per-region budgets, stable order,
one expanded bundle per root per level, and maximum three child edges are
PROJECT_OPERATIONAL_POLICY, not SOURCE_RULE, Elliott degree, or terminality.
No new protected principle identifier or source classification is created.

## Stop and coverage semantics

Monthly is the root observation resolution because it is the largest preserved
view; this is not a Primary/Cycle/etc. assignment. The explicit successor list
is Weekly, Daily and 1H. Every level uses a fresh genuine API invocation with
its exact parent requirement. All available child contexts at that invocation
are retained; only the first nonempty compatible bundle is expanded further.
Selection depends on API availability and deterministic enumeration, not on
P004/P005 results or relative family quality.

At each stop the output lists available bundles, expanded count and the exact
unvisited parent requirement IDs. Zero compatible bundles, missing finer data,
branch budget and level budget are not terminal Elliott proof.

Coarsened root proposals do not purport to inspect every intermediate pivot.
Regional windows are independent contexts, never stitched into one count.
The report must not label cross-region gaps as examined history.

## Delivery/visual contract

Use the established repository Markdown/JSON/CSV report convention rather
than introducing a new hosted app or HTML reporting stack. The requested
linked tree/table is an identity-and-operand lookup: compact tables are more
honest than a chart implying a continuous approved wave count. No chart or
new UI is needed. Build-report technical structure maps to summary,
capabilities, definitions, coverage/method, linked evidence, limitations and
next decision; validate-data supplies source/identity/count QA.

Current-position rejection is conservative infrastructure reporting, not a
new Elliott rule. If future work seeks positive current-position claims, it
must separately define a hypothesis-bound developing-position contract.
This stage neither drafts new source doctrine nor adopts such a contract.
