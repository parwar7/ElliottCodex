# MANUAL-STRUCTURE-CANDIDATE-INPUT-BUILDER-V1

This additive logical baseline records `PROJECT_ANALYSIS_INFRASTRUCTURE`. Its finite builder mapping, ordering, duplicate, binding-construction, and pass-through conventions are `PROJECT_OPERATIONAL_POLICY`, not Elliott methodology.

`MethodologyKernel.analyze_manual_candidate` accepts only one exact live `ManualStructureCandidateRequest`. It converts six approved exact caller-declaration types into exact existing methodology input objects, wraps them in `ExplicitBehaviorInput`, and delegates to the existing `analyze_candidate_inputs` pipeline. It does not construct methodology results or duplicate downstream execution and orchestration semantics.

Every supported declaration reports `CALLER_SUPPLIED_STRUCTURAL_FACT`. This classification means untrusted workflow input only; it is not source authority, proof, methodology result, certificate, family, validity, or applicability. Manual fact type—not a caller-supplied behavior ID, constructor, callable, module, or class name—selects one entry in a private immutable finite builder table.

The approved facts cover explicit P004 operands, explicit peer-degree nodes, explicit parent/child degree labels and statuses, explicit P023 visibility, explicit P003 relative relation, and an explicit cardinality behavior selector. Cardinality selection is mandatory: child count never selects single zigzag, flat, triangle, or ending diagonal. Prices must be explicit finite numeric observations; degrees, direction, relation, and visibility must use their exact existing tokens. Nothing is derived from observations, bars, timeframe, duration, or combined facts.

An exact existing child binding may be supplied, or the builder may construct one `OrderedChildBinding` from an exact parent, explicit binding ID, and exact ordered child-subject tuple. It does not reorder, deduplicate, discover, label, or infer parentage. Cardinality inputs retain that exact effective binding.

No ordinary manual fact maps to no-rescue and no certificate is synthesized. Existing genuine live structural-invalidity certificates may pass through a separate exact dependency tuple, subject and binding checked, to the existing no-rescue execution. Automatic certification remains absent.

The result retains the exact request, effective and newly constructed binding identities, ordered exact `ExplicitBehaviorInput` objects, and exact delegated `ExplicitBehaviorExecutionResult`; its downstream `SingleCandidateAnalysisResult` remains authoritative only within its existing limits. Zero facts delegate to the existing conservative `UNRESOLVED / NO_METHODOLOGY_EVALUATIONS_SUPPLIED` behavior.

Request, fact, mapping, and result boundaries reject mappings, ducks, subclasses, dynamic dispatch, duplicate fact identity, cross-subject data, mismatched bindings, malformed numeric/token inputs, low-level mutation, and pickle restoration. This remains a development logical baseline without physical immutability, hostile same-process isolation, cryptographic authenticity, or durable cross-process authority.
