# Rendering boundary audit

## Chart contract

Question: where does one saved scenario lie in observed history, and which child hypotheses are genuinely linked to it?

Takeaway: evidence covers historical proposed scenarios only; it does not identify the current wave. A full-range price overview is paired with an automatically fitted selected-scenario detail chart and exact endpoint lookup table. Linear USD axes are display choices, not methodology. Monthly/Weekly close series are factual context; dashed role segments preserve saved high/low operands. Only the selected interpretation is plotted. Blue observation marks and orange proposed marks use shape/dash/text distinctions; rejection and unresolved states are written explicitly, never inferred from color.

The required hierarchy selector, exact per-requirement child navigation and scenario reach panel need a standalone interactive chart viewer rather than a generic report's static chart blocks. The primary deliverable is that requested custom viewer. The visualization workflow informed the chart/table choice, two-color palette, responsive/system-theme layout and browser QA; no hosted or in-conversation artifact was substituted.

## Read-only evidence path

1. Verify the approved scoped baseline manifest and all its artifact entries.
2. Verify the saved input manifest and four normalized input files.
3. Reuse the prior read-only audit: 612 endpoint occurrences, 90 hypotheses, 63 child-context links and 84 search scopes reconcile against actual saved observations. The prior comparison is audited for provenance, but only its after results are projected.
4. Export exact selected evidence fields and display-only reach/price-text fields. Recompute the projection to reject any changed labels, coordinates, basis, timestamps, snapshots, statuses, parent links or search accounting.
5. Embed exactly that JSON, with HTML/script delimiter escaping and `connect-src 'none'`. DOM text uses textContent; source strings are not executed as markup. No CDN, fetch, credentials, dynamic code evaluation or server is required.

No original artifact is mutated. No methodology evaluator, shared contract, provider, candidate generator or certification registry is changed or invoked to generate results. Importing existing report loaders does not authorize or invoke their live capture/generation entry points.

## Coverage and interpretation

- Three selected scale-2 historical roots, 27 parent hypotheses, 63 child occurrences, 84 unsatisfied requirements. Repeated endpoint sequences preserve every original context and are never counted as independent confirmations.
- Parent Normal Impulse: P004 violated 3; P005 sufficient 2 / unresolved 1. The two sufficient-and-P004-rejected parents remain visibly rejected.
- Child Normal Impulse: P004 satisfied 6; P005 sufficient 3 / unresolved 3. No full family validation follows.
- Child search window contexts: selected 18, operationally excluded 98, unvisited by budget 116. Scope reasons include insufficient pivots (60 requirements), no selected-domain sequence (6), and first eligible scope selected (18). These are not counts of invalid waves.
- Missing children remain absent. No endpoint-equality joins, fabricated subdivisions, deeper recursion, closed-world proof, timeframe-degree mapping or preferred ordering is introduced.
- Existing normalized records are historical snapshots, not reconstructable raw Yahoo responses. Source response hashes remain provenance, and no claim is made to recompute raw-response hashes from normalized data.
- Last plotted labels are not active-wave evidence. All 90 reach panels remain `CURRENT_WAVE_POSITION_UNRESOLVED`, retaining exact trailing-unassigned-bar counts and concrete saved reasons. Developing geometric endpoint metadata, if present, does not become a genuine bound developing Elliott component; absence does not prove completion.

## Adversarial and visual checks

Focused regressions cover exact projection equality, changed price/role/date/status/snapshot/parent rejection, alternative isolation, repeated-coordinate retention, missing children, stale capture, unresolved current position, developing geometry non-promotion, missing/partial coverage, search dispositions, HTML payload escaping, manifest mismatch and zero family authority.

Installed Edge browser QA visits every parent and child through actual controls, checks one plotted interpretation, exact role labels/table timestamps/prices, exact child-link sets and return navigation. It checks JSON download equality, desktop/mobile widths, light/dark system themes and no external page requests or page errors. A narrow-layout overflow found during development was fixed by allowing long evidence states to wrap; no evidence changed. The final full-page screenshot was inspected for layout and readability. Browser QA does not certify other browser engines, touch interactions or print conversion.

See `tests.json`, `integrity.json`, `render_audit.json` and the hash manifest for final receipts. A full regression run is performed once after final implementation changes. No new methodology finding or project-manager approval is asserted.
