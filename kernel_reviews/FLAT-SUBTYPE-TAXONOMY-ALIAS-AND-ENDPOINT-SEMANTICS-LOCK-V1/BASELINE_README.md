# FLAT-SUBTYPE-TAXONOMY-ALIAS-AND-ENDPOINT-SEMANTICS-LOCK-V1

This additive logical baseline locks a source-bound Flat subtype vocabulary and a hypothesis-only evaluation boundary. It does not classify a Flat, validate a family, rank alternatives, or execute a new Elliott rule.

The protected sources support three known subtype names: Regular Flat, Expanded Flat, and Running Flat. Frost/Prechter explicitly identifies Elliott's historical “irregular flat” name with the Expanded Flat variation. The taxonomy is recorded as `KNOWN_SUBTYPES_NON_EXHAUSTIVE`; generic `FLAT` remains available independently and no closed-world inference is permitted.

The implemented Runtime layer fans each exact parent or recursive-child `FLAT` evaluation hypothesis into all three subtype `evaluate-as` hypotheses. It consumes exact endpoint/path evidence and preserves the exact proposed A start, A end, B end, and C end pivot identities. These are hypothesis-bound proposed component endpoints, never globally promoted orthodox Elliott endpoints.

No hard subtype endpoint behavior is implemented. Protected wording such as approximately, near, slightly, substantially, well beyond, and rare does not provide a deterministic tolerance or magnitude. Equality, completion/developing scope, and some endpoint-versus-whole-path semantics are also not fully locked. Those conditions remain frozen for a future separate methodology approval.

The NVDA experiment used one cohesive Yahoo retrieval snapshot and bounded evaluation on Monthly→Weekly, Weekly→Daily, and Daily→1H scopes. Counts describe evaluate-as hypotheses only; validated Flat subtypes remain zero and ranking remains absent.

This baseline is logically write-once during development. Physical sealing is not claimed.
